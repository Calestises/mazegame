一、功能需求
1. 基本运行需求
程序启动后应显示开始菜单，允许用户选择：
1.新游戏
2.读取存档

2. 地图生成需求
程序应能自动生成一张迷宫地图。
地图应包含：
1.墙
2.可通行道路
3.起点
4.门
5.钥匙
6.传送点

3. 玩家操作需求
玩家应能通过键盘进行操作：
1.w：向上移动
2.s：向下移动
3.a：向左移动
4.d：向右移动
5.p：保存游戏
6.o：读取存档
7.q：退出游戏

4. 游戏规则需求
玩家在迷宫中移动时：
1. 不能穿墙
2. 不能走出地图边界
3. 未收集全部钥匙前不能进入门
4. 踩到钥匙后应自动拾取
5. 踩到传送点后应自动传送
6. 收集全部钥匙并进入门后应判定为通关

5. 存档读档需求
程序应支持将当前游戏状态写入文本存档。
程序应支持从文本存档中恢复游戏状态。
存档内容应至少包含：
1. 地图大小
2. 玩家位置
3. 起点位置
4. 门位置
5. 钥匙数量
6. 传送点数量
7. 整张地图数据
8. 传送点坐标

6. 界面显示需求
程序应在控制台中显示：
1. 游戏标题
2. 当前钥匙进度
3. 操作提示
4. 图例说明
5. 当前迷宫地图

7. 结束需求
玩家通关后，程序应显示胜利信息。
程序结束前应恢复控制台光标显示。


三、软件逻辑结构

6. 退出前暂停

1. hidecursor
2. showcursor
3. setupconsole

5. pauseandexit

1. 生成存档文件完整路径

1. getsavefilepath
2. seedrandom

3. 地图生成模块
功能：
1. 先将整张地图填为墙
2. 再通过随机挖路生成迷宫

对应函数：
1. fillwalls
2. changedirect
3. makemaze

4. 地图分析模块
功能：
1. 计算从起点到各位置的最短距离
2. 统计某个格子周围有几条可通路
3. 根据条件寻找合适的道具摆放点
4. 选择门的位置

对应函数：
1. bfsdisrance
2. countopenaround
3. findplace
4. choosedoor

5. 道具配置模块
功能：
1. 设置钥匙总数
2. 选择钥匙位置
3. 选择传送点位置
4. 记录传送点坐标

对应函数：
1. additems

6. 游戏初始化模块
功能：
1. 清空旧状态
2. 生成新地图

7. 显示模块
功能：
1. 将地图内部字符转换成适合显示的图案

8. 传送与移动模块

9. 存档模块
功能：
1. 将当前游戏状态写入文件

对应函数：
1. savegame

10. 读档模块
功能：
1. 从文件中恢复游戏状态

对应函数：
1. loadgame

11. 输入与主控制模块
功能：
1. 读取单个按键
2. 控制开始菜单
3. 控制游戏主循环
4. 根据按键调用不同功能

对应函数：
1. readkey

四、软件代码说明

1. hidecursor
功能：
隐藏控制台光标，避免游戏刷新时看到闪烁输入光标。

输入：
无

输出：
无

关键点：
通过 Windows 控制台 API 获取并修改光标可见性。

2. showcursor
功能：
恢复控制台光标显示。

输入：
无

输出：
无

关键点：
程序结束前调用，保证终端状态正常。

3. setupconsole
功能：
初始化控制台输出环境。

输入：
无

输出：
无

关键点：
1. 获取控制台输出句柄
2. 设置输入输出编码为 UTF-8
3. 隐藏光标

4. clearscreen
功能：
清空控制台当前画面。

输入：
无

输出：
无

关键点：
调用 system("cls") 重绘控制台界面。

5. pauseandexit
功能：
在通关后暂停，等待用户按键。

输入：
无

输出：
无

关键点：
通过 _getch() 实现“按任意键继续”。

6. getsavefilepath
功能：
得到存档文件完整路径。

输入：
1. buffer：接收路径的字符数组
2. size：数组容量

输出：
无，结果写入 buffer

关键点：
优先将存档放在 exe 所在目录，而不是依赖当前工作目录。

7. seedrandom
功能：
初始化随机种子。

输入：
无

输出：
无

关键点：
使用 static 变量保证 srand 只执行一次。

8. fillwalls
功能：
将地图全部初始化为墙。

输入：
1. game：游戏状态结构体地址

输出：
无

关键点：
1. 设置地图行列数
2. 将 map 全部填成 '#'
3. 每行最后补 '\0'

9. changedirect
功能：
随机打乱四个方向顺序。

输入：
1. dirs[4]：方向数组

输出：
无，直接修改原数组

关键点：
用于让迷宫挖路顺序随机化，避免每次迷宫结构完全固定。

10. makemaze
功能：
在全墙地图上挖出迷宫通路。

输入：
1. game：游戏状态结构体地址

输出：
无

重点功能说明：
这是迷宫生成的核心函数。
程序从起点 (1,1) 开始，使用类似深度优先搜索和回溯的方式挖路：
1. 当前点随机尝试四个方向
2. 目标点按“两格前进”计算
3. 如果目标位置仍是墙，就打通中间墙和目标点
4. 若四个方向都无法继续，则回退到上一个点

这样可以生成一张具有路径分支的随机迷宫。

11. bfsdisrance
功能：
计算起点到整张地图各个可达位置的最短距离。

输入：
1. game：游戏状态
2. startRow：起点行
3. startCol：起点列
4. dist：保存距离结果的二维数组

输出：
无，结果写入 dist

重点功能说明：
这是地图分析的核心函数。
程序通过广度优先搜索逐层扩展：
1. 起点距离为 0
2. 相邻可达位置距离加 1
3. 墙和已访问位置不再重复进入队列

它的结果会被后续多个功能复用，例如：
1. 选择最远门位置
2. 选择较远钥匙位置
3. 选择较远传送点位置

12. choosedoor
功能：
把门放在离起点最远的可到达位置。

输入：
1. game：游戏状态

输出：
无

重点功能说明：
先调用 bfsdisrance 得到距离表，再遍历地图找到距离最大的非墙位置，将其设置为门。
这样可以保证终点不会离起点太近。

13. countopenaround
功能：
统计某个格子上下左右有几个位置不是墙。

输入：
1. game：游戏状态
2. row：目标格行
3. col：目标格列

输出：
1. 返回可通方向数量

重点功能说明：
这个函数常用于判断某个格子是否接近“死路尽头”。
如果周围只有 1 个可通方向，通常说明该点在路径尽头。

14. findplace
功能：
在地图中寻找一个满足条件的可放置位置。

输入：
1. game：游戏状态
2. dist：距离表
3. minDist：最小距离要求
4. needDeadEnd：是否要求必须是死路
5. result：输出结果坐标

输出：
1. 找到返回 1
2. 找不到返回 0

重点功能说明：
这是程序中“智能选点”的核心函数。
它并不是随便找空地，而是分步骤筛选：
1. 必须是普通路 '.'
2. 不能是起点
3. 必须离起点达到一定距离
4. 如果要求死路，则周围开放方向必须为 1

若某个距离要求下找不到位置，它会逐步降低距离要求继续尝试。
这能避免由于迷宫结构特殊而完全找不到位置。

15. additems
功能：
在迷宫中加入钥匙和传送点。

输入：
1. game：游戏状态

输出：
无

重点功能说明：
1. 先计算起点到全图的距离
2. 设置总钥匙数为 2
3. 将钥匙优先放在较远且接近死路的位置
4. 将传送点放在较远的可通位置
5. 同时记录传送点坐标到 teleports 数组

16. setnewgame
功能：
初始化一局新游戏。

输入：
1. game：游戏状态

输出：
无

重点功能说明：
这是“新游戏入口函数”，负责依次完成：
1. 清空旧数据
2. 填墙
3. 生成迷宫
4. 设置起点和玩家初始位置
5. 放置门
6. 放置钥匙和传送点

17. printmap
功能：
将地图内部字符转换为适合显示的字符。

输入：
1. tile：地图格字符

输出：
无，直接打印到控制台

关键点：
1. '#' 显示为 █
2. '.' 显示为空格
3. 其他字符直接输出

18. drawgame
功能：
将完整游戏界面输出到控制台。

输入：
1. game：游戏状态

输出：
无

重点功能说明：
这是界面渲染函数，负责：
1. 清屏
2. 打印标题和状态信息
3. 打印操作提示和图例
4. 逐格输出地图
5. 玩家位置单独显示为 @

19. getteleporttarget
功能：
根据当前传送点位置，找到目标传送点位置。

输入：
1. game：游戏状态
2. row：当前传送点行
3. col：当前传送点列
4. targetRow：输出目标行
5. targetCol：输出目标列

输出：
1. 成功找到返回 1
2. 找不到返回 0

重点功能说明：
当前设计采用循环传送方式：
1. 若踩到第 i 个传送点
2. 就传送到第 i+1 个传送点
3. 最后一个再回到第 0 个

20. savegame
功能：
保存当前游戏状态到文件。

输入：
1. game：游戏状态

输出：
1. 成功返回 1
2. 失败返回 0

重点功能说明：
保存内容包括：
1. 地图大小
2. 玩家位置
3. 门位置
4. 钥匙状态
5. 起点位置
6. 传送点数量
7. 整张地图
8. 所有传送点坐标

21. loadgame
功能：
从文件中恢复游戏状态。

输入：
1. game：游戏状态

输出：
1. 成功返回 1
2. 失败返回 0

重点功能说明：
它与 savegame 成对使用，负责按保存顺序把数据读回程序。

说明：
当前版本中，loadgame 的基本逻辑是成立的，但其中 teleportCount 的检查顺序仍可继续优化。
这属于后续可改进点，不影响本文档对当前版本结构的说明。

22. moveplayer
功能：
处理玩家移动及移动后的事件逻辑。

输入：
1. game：游戏状态
2. dr：行变化量
3. dc：列变化量

输出：
1. 返回 0：移动失败
2. 返回 1：移动成功但未通关
3. 返回 2：移动成功且通关

重点功能说明：
这是玩家行为逻辑的核心函数，处理顺序如下：
1. 先计算目标位置
2. 判断是否越界
3. 判断是否撞墙
4. 判断门是否可进入
5. 更新玩家位置
6. 判断是否踩到钥匙
7. 判断是否踩到传送点
8. 判断是否进入门并通关

23. readkey
功能：
读取单个键盘按键。

输入：
无

输出：
1. 返回按下键的字符值

关键点：
使用 _getch()，因此按键不需要回车。

24. main
功能：
程序主入口。

输入：
无

输出：
1. 返回程序退出状态

重点功能说明：
主函数控制程序整体流程：
1. 初始化控制台
2. 初始化随机种子
3. 显示开始菜单
4. 决定新游戏或读档
5. 进入游戏主循环
6. 每轮绘制游戏并读取按键
7. 根据按键调用移动、保存、读档、退出等功能
8. 通关后显示胜利信息并暂停
9. 最终恢复光标后退出


五、重点功能总结
1. 随机迷宫生成
由 fillwalls、changedirect、makemaze 组成。
这是程序地图生成的核心基础。

2. 基于 BFS 的位置分析
由 bfsdisrance、choosedoor、findplace 组成。
这是程序“不是乱放门和道具”的关键。

3. 玩家事件处理
由 moveplayer 负责。
这是玩家操作和游戏规则的核心连接点。

4. 存档与读档
由 savegame、loadgame 负责。
这是程序可持续游玩的基础。


六、可继续改进的方向
1. 统一命名风格
当前代码中存在连写风格，后续可统一。

2. 提高读档合法性检查严谨性
例如 teleportCount 的检查顺序可以进一步调整。

3. 增加错误提示
目前保存失败或读档失败时主流程没有显示专门提示文字，可继续增强交互体验。

4. 增加更多地图规模和玩法参数
例如：
1. 可调地图尺寸
2. 可调钥匙数量
3. 可调传送点数量


七、结论
当前版本的 mazegame.c 已形成一个结构较完整的控制台迷宫小游戏。
它具有迷宫生成、道具放置、玩家移动、传送、存档与读档等完整功能。
从软件工程角度看，该程序虽然规模不大，但已经具备：
1. 基本模块划分
2. 明确函数职责
3. 可维护的主流程结构
4. 可扩展的功能基础
